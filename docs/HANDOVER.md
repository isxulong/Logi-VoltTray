## 4. 红线与纪律（违反即返工）

- **D-33 零耗电红线**：任何设计不得以消耗鼠标电池为代价。禁高频轮询；禁对休眠设备主动探测保活；休眠恢复走被动 RawInput 事件。量级参照 D-66（一次 HID++ 查询 ≈2 个射频包，60s 轮询一天 ≈3s 主动使用的射频成本）。事故史：D-67（v0.3.9→v0.3.10 休眠误判致 30s 探测）、经验 E18 P1-1（v0.3.15 唤醒旁路 0.5Hz 查询风暴，约为 1800s 档的 900 倍）。
- **双独立复核**：所有代码批次（含纯删除）须全栈代码质检官 + 高级开发工程师各自独立复核、互不看对方报告，两席均放行才过；细则见 docs/ai-orchestration.md（2026-10-25 落库生效）。纯文档批次（docs/** 或 *.md）可豁免，但须派发人显式声明。
- **凭证纪律**：GitHub PAT、签名材料永不入 git、不入日志、不入评论。PAT 开工时向用户重新索取（fine-grained，Contents: Read and write）。
- **git 操作**：沙箱内 github.com 的 git 端点 502 不可用；一律走 api.github.com Git Data API（blobs → tree → commit → update ref），fast-forward，绝不 force push。
- **推送前安全扫描**：keystore / 密码 / PAT 模式零命中。
- **CI 纪律**：推送后用 API 核实 check-runs；nightly 可用 workflow_dispatch 手动复跑；workflow 脚本一律步级钉工作目录或用 $GITHUB_WORKSPACE 绝对路径，不得吞 stderr（经验 E39）。
- **协作纪律**：只与「研发小组长」单会话对话；里程碑由主 AD 汇总统一推送用户；不接受任何成员自述替代独立取证（经验 E40）；派发后修改规格要当心——任务描述更新对已启动的执行不生效（经验 E42）。
