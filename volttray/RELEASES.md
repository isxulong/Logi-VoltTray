# 发布说明

## v0.3.20

红蓝对抗（R1）系列收官版：两项用户向修复 + 托盘菜单两项新增 + 工程质量体系全面升级。（本节说明与 [GitHub Release v0.3.20](https://github.com/isxulong/Logi-VoltTray/releases/tag/v0.3.20) 正文一致。）

### 修复（两项，均来自 R1 对抗找茬）

- **配置写丢档窗口修复（T-01）**：导出与配置落盘的 tmp→rename 写入删去覆盖前的删除步骤，rename 原子覆盖既有目标——此前写入中途失败可能出现目标文件丢失，本版起该窗口消除。
- **诊断导出隐私改进（T-02a）**：诊断导出 JSON 现自动执行文本侧脱敏——本机用户名（`C:\Users\<名>` 路径段，覆盖 USERPROFILE/APPDATA/LOCALAPPDATA 前缀主干）替换为 `<USER>`，设备名按出现顺序替换为「设备N」。**存量披露**：v0.3.20 之前版本导出的文件可能含本机用户名与设备名，请在提交前自行检查删除。

### 新增（托盘菜单两项）

- **功能分级标注（T-04）**：菜单中未验证档位的 direct 项明确标注，枚举失败时给出兜底行；README 增补实验性小节。
- **「检查更新（当前 vX）」菜单项（T-07）**：点击经系统默认浏览器打开发布页（ShellExecuteW，零网络依赖形态）。

### 兼容性

无破坏性变更。菜单两项均为新增行，不改既有项的默认值与显示行为；配置键无语义变更、无需迁移；T-01 属写入路径修复（失败窗口消除），不改变成功路径行为。唯一行为面变化是诊断导出内容按上述口径脱敏（有意改进）。

### 下载与安装注意

本软件 EXE 未经商业代码签名，Windows SmartScreen 首次运行可能提示「Windows 已保护你的电脑」——点「更多信息」→「仍要运行」即可。这是未签名软件的常态提示，非病毒告警。唯一分发形态为 Rust EXE（Python 双轨出货已停，Python 版保留为协议参考实现）。

### 工程与质量（开发者向摘要）

本版合入 R1 红蓝对抗 26 项补丁（22 项采纳 + 3 项修正后采纳，全程门禁化 PR 合入）：发布门禁（release.yml 构建前强制复用 ci.yml 全量前置）、nightly fuzz 真实烟测 + 失败自动开单、cargo audit 周检 + 失败自动开单、Ubuntu CI 门禁、verify.sh 本地自检、诊断导出字段审计（T-02b）、fmt 债清偿、README 中英文与上手指引大面积失实修订、隐私披露断点统一锚定 v0.3.20。nightly fuzz 门禁已实跑全绿（5 分钟 1.42 亿次执行零崩溃）。

## v0.3.19

**自启动换版失效自动修复（五轮红蓝对抗 U-7）**：旧版勾选「开机自启」后，exe 文件名带版本号升级换版（删旧版、放新版）时，注册表自启项仍指向旧版路径——开机自启静默失效且设置界面仍显示「已开」。本版启动时自动对账修复，无需手动关→开。

### U-7 启动自愈对账

- **修复内容**：启动时按「配置 × 注册表」四格矩阵收口——配置开＋注册表值缺失 → 自动重建；配置开＋注册表路径已换版（含等长版本号改名，如 v0.3.18→v0.3.19）→ 自动重写为当前 exe 完整路径（用户手工附加的自启参数保留）；配置关＋注册表残留旧值 → 自动清理；状态一致 → 不动。自愈成功静默完成、仅记启动日志一行，不弹任何通知。
- **语义边界（披露）**：①「配置开＋注册表值被手动删除」与「路径失效」同等自愈（无法也无需区分用户意图——值缺失后任何重建都以配置为准）；② 显示语义维持「注册表值存在即开」不变；③ 路径比较按 Windows 规范化（大小写不敏感、正/反斜杠、长路径前缀、尾部斜杠、重复反斜杠、成对引号），无法判定的形态一律保守判不等并收敛重写为规范式，不会出现「实际不同却判等」。
- **失败可见性**：注册表读失败 → 诊断流一次性告警；写/删失败 → 沿用既有失败语义（共享配置回退为注册表现状＋落盘＋告警），不会反复重试刷 UI。
- **开发态防护**：debug 构建跳过一切自动注册表写，调试不再污染真实自启项；注册表读取与界面显示不受影响。门控范围披露：debug 门控仅覆盖本版新增的启动期自愈对账；既有的配置变更同步（cfg_changed 回路）与「恢复全部默认」的注册表写入行为维持原状、与旧版一致。
- **残余风险（有意划界）**：① 8.3 短文件名（`PROGRA~1`）不展开——命中时按不匹配处理并收敛重写为长名规范式，不产生死值；② 开启目录级大小写敏感的 WSL 生态目录下，仅大小写不同的两条路径可能指不同文件——该场景按同一文件处理（NTFS 默认口径）；③ 无引号形态（无论是否含空格）的旧值（非本程序写出的形态）参数段不保留，收敛重写为带引号规范式。④ 安装路径超过 260 字符且系统未启用长路径策略（LongPathsEnabled）时，Run 值任何形态均无法被开机链拉起——Windows Run 键固有限制，非本版可治，不引入 8.3 短名转换。

### 工程约束（红蓝对抗裁决）

- 路径比较为纯字符串规范化（无 I/O），Rust 单元测试跨平台随 CI 全量运行（新增 24 例）；python 协议测试 80/80 保持通过；无新增 unsafe（注册表读值并入既有查询块，unsafe 块数较基线零新增）；零新依赖；配置键 `autostart` 语义不变、无需迁移标记。

## v0.3.18

设置窗口外观区六问题终审修复（四轮红蓝对抗 U-1~U-6）：文本大小基准重定、预览收敛为单一渲染源、大字体裁切根治、对比度警告条移除。**兼容性声明：文本大小默认值由 100% 上调至 140%（存量未改过的配置自动迁移，详见 U-1）。显示突变面（均为修复裁切与单调性 bug 的有意行为变化）：① 极端档位（粗字重 × 高百分比）下图标字高可能略缩；窄字形字体处字高可能略增，size=24 位图高档位（ts≥150）同向略增；② 宽字体（如 Arial Black）高文本档位用户：托盘常态帧文本经实测预缩收回背景块内，字高可能略小。**

### U-1 文本大小基准重衡量（默认 100% → 140%）

- **基准查证（去代码里查证所得）**：百分比锚定**图标位图边长**——100% = 字高 = 位图边长 × 5/8（≥2 字符）/ × 3/4（单字符），该几何自 v0.3.3 起冻结至今未变。96dpi 下位图 16px，100% 档字高仅 10px，对多数用户确实偏小。
- **新默认值 140%**：96dpi、两位数字在 140% 档字高恰好触顶（位图安全边 14px），是 96dpi 下的有效上限（140 在 96dpi 档等同旧 160，高 DPI 档 ±1~2px）；滑块范围维持 40–160（配合滚轮精调与高 DPI 位图放大的余量）。文本大小上限维持 160：>160 后渲染输出被几何上限锁死，扩上限需改渲染几何，已另立变更。
- **存量迁移（硬要求）**：新增 `icon_text_scale_migrated_v0318` 标记键——配置文件**无此标记且值为 100** 视为「从未主动调整」，升级时自动迁移到 140 并告警写回标记（幂等，不重复迁移）；无标记但值非 100（用户主动调过）保持原值、静默补写标记；**已知误伤面披露：显式写过 `icon_text_scale = 100` 的存量配置无法与「未调整」区分，会被一并迁移**——受影响用户请在设置里调回 100（标记键对旧版本属未知键，降级使用不产生告警，回退安全）。
- **BF-1 缩字单调性修复（顺带根治）**：旧实现按安全边/估算宽度比例缩字，整数截断下非单调（24px 位图时 160% 档字高反比 140% 档矮 1px）——档位更高字却更小，与档位语义矛盾；改为逐档递减字高直至估算宽度收敛，全位图档位 × 全文本档位字高单调不减（测试锁定）。

### U-2 / U-3 预览收敛（删小预览、大预览 144px 无倍数标注）

- **U-2 删除小预览**：「任务栏实际效果」1× 预览整体移除（用户可直接看真实任务栏，死示例多余）；外观区行高重排，无残留空位。
- **U-3 大预览改 3×、去倍数标注**：大预览画布由 192px（4×48 基准）收敛为 144px（3×48 基准），标签仅写「预览」不再标注倍数；位图按 K = max(1, 画布 ÷ 真实位图边长) 取整最近邻放大并居中，画布外区域棋盘格衬底——预览只负责看布局，大小以任务栏为准。

### U-4 大字体裁切根治（探针画布机制）

- **根因**：旧实现按字符宽度估算选字高，粗字重字体（如 Arial Black）真实墨迹超出估算，160% 档在大预览中底部裁切、未居中（图2）。
- **探针重构**：文字先画到（位图边长 + 2×安全边）的探针画布正中，逐像素扫描真实墨迹包围盒（ink_bbox）；包围盒放不进背景块则按字高 1/8 步长收缩重画（上限 32 次）；最终合成时以墨迹包围盒为中心开窗拷贝回位图——**居中与缩字都按真实墨迹判定，不再依赖宽度估算**，任何字体、任何档位墨迹必然完整落在背景块内（测试锁定：Arial Black @160% 全墨迹落块；GDI 字体回退路径同受约束）。

### U-5 单一渲染源（预览 = 真实托盘渲染结果）

- **根因**：预览与任务栏曾是两套相似实现，预览显示背景包裹文字、真实任务栏却溢出（图3），预览不可信。
- **实现路径**：图标渲染核心新增 `render_frame_rgba` 公开出口（与托盘共用 `render_frame` 同一函数、同一位图管线，固定常态帧 bright=false）；设置窗口每次刷新用当前表单配置临时构建 IconCache 直接渲染，大预览显示的即是该配置下任务栏将出现的同一张位图的整数倍放大——**预览与任务栏在像素级同源，外壳（圆角/形状/覆盖度）差异不复存在**。同源口径以应用交付的图标位图为界，系统侧 DPI 缩放与主题呈现超出渲染管线控制；预览为打开时电量／dark／tray_size 快照，关窗重开即一致。

### U-6 删除对比度警告条

- 「字色与背景对比度低于 3」提示条整体移除：软件在透明背景下无法获知任务栏真实颜色，对比度计算的前提不成立；效果用户一眼可见，不需要提醒。设置窗口高度 842 → 816，「恢复全部默认」按钮上移补齐。

### 验证口径

- python 协议测试 80/80（tests/ 全绿）；Rust 单元测试含本次新增 3 例（迁移幂等、缩字单调、粗字重落块）＋更新既有默认值与钳制断言，走 CI（windows-latest，--locked，工具链 1.90.0）；零新增 unsafe（沿用既有 GDI 块）；clippy -D warnings 零告警口径（死代码/未用导入随删除项全清）。

## v0.3.16

v3 设计包整体落地：D-72 电量图标「?」/ 误报离线修复 + WP-A 持久化与休眠 + WP-C 按设备计时轮询 + WP-B 耗电统计。全程遵守零鼠标电耗红线（休眠设备零主动查询，统计只消费已有轮询/唤醒读数）。

### 误报离线修复（D-72）

- **根因**：90 秒灰显规则（GRAY_AFTER）纯墙钟派生与轮询档位（300~7200 秒）结构性矛盾——v0.3.15「探测轮跳过在线设备」使在线设备 last_success 冻结到下一次整轮，90 秒后误灰显、误报「设备离线」toast、默认图标回退「?」。
- **探测轮临近到期豁免**：在线设备临近自身下次轮询到期点 30 秒内时，探测轮放行一次查询；正常使用中读数间隔被自身档位 + 豁免收敛，不再因档位冻结误灰。仅对在线设备生效，与休眠唤醒探测按状态互斥，同轮不会双查；充电档排除在豁免外（30 秒提前量会破坏 15s±2s 节拍）。WP-C 落地后豁免锚统一迁移为「按设备 next_due」，非两套并存。
- **阈值锚定兜底**：灰显阈值 = max(90s, 2 × 本设备轮询档)，灰显判定/快照/默认显示设备选取统一走按设备锚定阈值。
- **显示层同权 + 文案修正**：在线 + 灰显与休眠同权保留展示资格（灰显显示最后已知电量，不再回退「?」；已断开 + 灰显仍排除）；toast 改为「电量显示已过期 / 已灰显最后一次已知电量」（原「设备离线 / 超过 90 秒未响应」在本路径下属虚假陈述）。
- **P2 降噪**：接收器 0xFF 槽位探测的 error_response 形态 BatteryUnknown 事件压入 bootlog debug 级，不再进诊断事件流；真离线检测链（DeviceGone 即时注销 / 超时×2→休眠 / 硬失败×3 注销）逐行未动。

### 持久化与休眠（WP-A）

- **last_known.json 持久化**：落 `%LOCALAPPDATA%\LogiVoltTray\`（与 config.toml 分离，规避 roaming profile），原子写 .tmp→flush→rename，损坏改名 .bak 回退空库不阻塞启动；变化驱动 + 防抖（同设备 ≤1/30s、全局 ≤1/10s），崩溃最坏丢 60 秒、掉电最坏丢 5 分钟。
- **虚拟条目重启即显**：重启后最后已知电量立即显示（is_virtual 虚拟条目，零设备查询）；有数据才启用菜单项（has_displayable_data）。

- **休眠唤醒通道归因**：唤醒按 Raw Input 设备路径归因通道，失配回退全量并计 channel_map_miss。

### 按设备计时轮询（WP-C）

- **三档按设备排程**：每台设备独立 `{next_due, tier}` 计时——充电 15s（POLL_CHARGING）/ 常规配置档（poll_interval_secs，默认 1800s=30min）/ 休眠 None（不排程，D-33 零查询红线不变）；充电切换即时生效，拔线感知延迟 ≤ 一个充电档。
- **整轮内按设备到期门**：每台设备自己的 next_due 决定自己的查询节奏，他设备充电不再抬高本设备频率（I-06：他设备充电时本设备拔电感知从 ≤15s 退化为 ≤30min，属 v3 明示口径）；full_poll_due 退役，睡眠预算 = min(全设备最近到期点, 重连唤醒点)。
- **配置热重载注意**：已排程设备的到期点在下一次读数前仍按旧档计时（灰显阈值实时读新配置），记录在案。

### 耗电统计（WP-B）

- **stats.jsonl 落盘**：读取事件 / 休眠进入 / 休眠唤醒首读 / run 启停 / 关机边界事件按行追加落盘；单文件 ≤10MB 触顶轮转（current → stats.archive.jsonl 覆盖式归档，双文件合计 ≤20MB），轮转前弹一次「统计历史即将轮转，建议先导出」提示。损坏行启动时跳过计数（skip-bad-lines），不阻断加载。
- **分状态归因**：读取时不预算，导出/展示时按时间轴分段——活跃 / 休眠 / 充电 / 未知四类。休眠段以 sleep_enter 为唯一起点（事实而非间隔推断）；run 边界强制断开，跨 run 缺口标未知（run_gap_unattributed）；sleep_enter 缺失标未知（evidence_missing），不回退间隔推断；时间倒流标 clock_anomaly、缺口 >7 天标 gap_over_7d，不产生负速率。不足 1 小时的段按确定性算法并入相邻同型段（一轮即止不级联），无法并入的标 below_window。
- **CSV 导出 + 自包含 HTML 报告**：托盘菜单「导出耗电统计…」可选同时生成 HTML 可视化报告与 JSON 原始事件序列。HTML 为单文件零外链（断网双击可开）：电量曲线（未知段断线 + 灰罩、充电段底色、单 polyline 无逐点元素）、每日耗电对比（活跃/休眠/未知三层，跨日段线性摊入标近似）、时长占比、分段明细（与 CSV 同数据同列）、近 7 天活跃耗速率；空态各图表显示「暂无数据」。
- **匿名化开关**：勾选后 device_key 显示为 D1、D2…（按 FNV-1a 哈希值字典序确定性编号，同一设备集跨多次导出编号恒定），覆盖 CSV / JSON / HTML 三路；display_name 保留真实值。

## v0.3.12

诊断导出增强（D-69）：真机实证——重启后识别失败时，导出的诊断 JSON 只有空数组 `[]`（旧格式 = 裸设备事件流数组，零设备时毫无信息量），远程排障还要二次索取 logi-volttray.log。本版把导出重构为对象，一次导出即带齐「设备事件流 + 日志尾部 + 最近枚举现场」。

### 修复

- **导出 JSON 由裸数组重构为对象（不兼容变更，向后兼容说明）**：旧格式是设备事件流的裸 JSON 数组（`[...]`）；新格式为对象，原事件流整体迁入 `devices` 字段（脱敏逻辑不动，P1-6 语义不变）。旧读端若直接把顶层当数组解析会失败——请改为取 `devices` 字段。新结构：`devices`（原设备事件流，锁中毒降级为空数组 + `devices_reason`）；`log_tail`（日志尾部 `{path, lines, reason}`，约 200 行）；`last_enum`（最近一次枚举快照，见下）或 `null`；`exported_at`（Unix 秒）；`app_version`。
- **`log_tail`：logi-volttray.log 尾部约 200 行**（`LOG_TAIL_MAX_LINES=200`）。三态语义：正常 → `lines` 尾部 200 行（顺序保持）；文件不存在 → `lines: []` + `reason: "log file not found: ..."`；文件为空 → `lines: []` + `reason: "log file is empty"`；其它 I/O 错误 → 空数组 + reason。**任何情况下导出不因此失败**（v0.3.2 「os error 3 让导出整体报错」教训：子项降级，不整体抛错）。
- **`last_enum`：最近一次枚举快照（内存状态）**：IO 线程每轮枚举后写入 `{at_ms, forced, candidate_channels, channels[{key, pid, tag, open, error}], registered_slots, error}`——候选通道数、各通道 open 结果（ok / failed / cached / reopened / cached-reopen-failed，含错误原因）、已注册槽位数、HidApi 初始化失败原因。导出时直接读内存，不打扰设备（零射频）；从未枚举（如导出先于首轮枚举）为 `null`；锁中毒降级为 `null` + `last_enum_reason`。快照写入锁中毒则本轮跳过，绝不影响主流程。
- **导出永远成功**：devices / log_tail / last_enum 任何子项失败各自降级为空 + reason 字段，导出整体永不报错；最终序列化失败兜底 `"{}"`。

### 零鼠标电池约束

导出为纯读操作：读内存（observer 事件流、枚举快照）+ 读日志文件，不对设备发起任何 HID 查询，零射频。

### 未验证项

tray 层（Windows 专属代码）无法在 Linux CI 编译之外的本地环境验证，Windows 运行时行为（菜单导出、枚举快照写入、日志路径解析）待真机验证；`read_log_tail` 三态（缺失/空/正常 250 行取尾 200）、快照 null/非空序列化、devices 脱敏保持已由 app 层单测锁定（6 例，diag_export.rs）。

### 启动失败可见化

- **崩溃日志**：启动全程写入 `%APPDATA%\LogiVoltTray\logi-volttray.log`（EXE 同目录 / %TEMP% 逐级兜底），记录各启动阶段里程碑与失败原因，超过 1MB 自动轮转。
- **失败弹窗**：单实例初始化、图标预渲染、托盘创建等关键步骤失败时，弹出中文错误提示并附日志路径，不再静默退出。
- **单实例可感知**：已有实例运行时再次双击，会弹出「LogiVoltTray 已在运行」并指引查看托盘位置，而不是毫无反应。
- **启动反馈**：每次成功启动发送静默通知「LogiVoltTray 正在运行」，说明托盘位置（通知失败仅记日志，不影响启动）。
- **panic 可见**：任何 panic 写入日志；GUI 线程 panic 额外弹窗提示。

> 诊断指引：若再遇启动异常，把日志文件（路径见上）发给开发者即可精确定位失败阶段。
