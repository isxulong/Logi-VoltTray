# E10 唤醒归因与试探额度体系设计文档（设计冻结 v1）

- 冻结日期：2026-10-31
- 覆盖条目：N-01（唤醒归因失效）、N-02（失败缓存优先级）、N-14（CSV 验收口径）、G-36 灰区打扰治理
- 实施依据：红蓝对抗 C 融合修复方案（E 终审签发）＋ D 差异补强三条（D-1/D-2/D-3 已裁决采纳）；终稿 E10 验收加厚三条
- 本文档为 E10 窗口唯一数值来源：zero-match 阈值、额度函数全部数值、保底周期 N、计数器清单在此写死；测试常量与本文档同源、漂移即红（见第 6 节同源机制）。

## 1. 背景与范围

真机实测：417 次唤醒仅 1 次归因成功（417:1），其余全靠逐通道试探，折算鼠标每天被主动叫醒约 1,500 次（估算口径）；试探频率约达说明书最密档 5.3 倍。本窗口不修「休眠零打扰」红线本体（D-33/G-36 红线文本不动），只治理「认不出设备时的打扰」与「归因失效」本身。

E10 验收加厚三条（终稿原文）：
1. 认不出设备的占比降到窗口开工时写死的阈值以下（→ 第 6 节）；
2. 强制重枚举兜底改测试态注入验收，不要求真机自然触发（→ 第 8 节）；
3. 设计文档必须裁决：每 5 秒全槽扫描与「读不到就本轮跳过」缓存谁优先、试探封顶与最低读数保障的关系（→ 第 2/4/5 节）。

## 2. 裁决一（N-02）：负缓存 / 死槽冷却优先于每 5 秒全槽扫描

**裁决：0xFF 负缓存与死槽冷却优先。** 「读不到就本轮跳过」的省电保护（D-76 R-1/R-2、D-90）在归因修复中不得被削弱：归因 miss 走 arm-all 时，被 0xFF 负缓存命中的通道本轮仍跳过（由既有 `ff_probe_suppressed` 纯函数门控，门控位置不变），死槽冷却中的槽位同样不戳。每 5 秒全槽扫描**不引入**。

理由：A/B/终稿三方同向；试探失败一次本轮不再戳是真机已验证的省电行为，拆这层保护会让鼠标被戳得更勤。归隐修复的收益来自「少 miss」，不来自「多戳」。

## 3. 裁决二（N-01）：归因两级匹配

现状：`wakechannel.rs` 的 `channel_fingerprint` 取「VID/PID 对＋实例路径前两个 `&` 分量」，精确匹配零命中即 miss（E22 单候选 VID/PID 兜底除外）。真机上实例路径分量漂移导致 417:1。

**两级匹配设计：**

- **第一级 hit_exact**：既有精确指纹唯一命中，语义零改动。
- **第二级 hit_relaxed**：指纹放宽到 **VID/PID＋MI（接口号）级**（实例路径只保留到 `MI_xx` 分量，去掉其后的动态分量）；放宽后候选恰 1 个 → hit_relaxed。
- **注册期绑定表消歧**：tray 主循环在每次枚举完成时建立「放宽指纹 → 物理身份（device_key）」绑定表（进程内存态、**禁持久化**——BvA-3：落盘即成脱敏注册表外新泄露面；确需落盘先入 REDACTION_RULES 并在 manifest 规则 id 集可见）。放宽后候选 >1 时，按注册实例前缀最长公共段对照绑定表消歧；消歧成功 → hit_relaxed。
- **歧义即 miss**：放宽后仍多候选且绑定表消歧失败 → 判 miss，走 arm-all 兜底（既有立场，不放大为误归因）。
- **单函数门控**：新旧匹配路径收敛于单一纯函数门控（参照 `ff_probe_suppressed` 先例），回滚 = 还原该单函数，不动其余代码。
- unitId 唤醒路径可得性：实现期验证；不可得则降级为纯前缀消歧（已预留降级路径，不阻塞本窗口）。

## 4. 裁决三（G-36 灰区）：试探额度函数（数值冻结）

**单一额度函数**（C-5 选 B：封顶与退避统一建模，不分两套常量）。逐设备、滚动 24h 窗口计数。

| 常量 | 冻结值 | 说明 |
| --- | --- | --- |
| `WAKE_PROBE_DEBOUNCE` | 5 s | 试探防抖专用常量（C-4 选 A；复用既有 `WAKE_PROBE_COOLDOWN=5s` 语义，**不碰** reconnect.rs `REENUM_INTERVAL=30s`——重枚举防抖与唤醒试探是两个机制）。**注：`WAKE_PROBE_DEBOUNCE` 即既有 `WAKE_PROBE_COOLDOWN`，不新增常量**——按本文档检索常量名时请直接查 `WAKE_PROBE_COOLDOWN` |
| `PROBE_BACKOFF_BASE` | 30 s | 退避序列最小试探间隔初值 |
| `PROBE_BACKOFF_MAX` | 1800 s | 退避间隔封顶（30 min） |
| `PROBE_DAILY_CAP` | 96 次 | 单设备滚动 24h 试探硬顶 |
| `PROBE_BACKOFF_FACTOR` | 2 | 连续未获确认读数（miss 或读数失败）时间隔倍增因子 |

**退避规则**：单设备连续试探未获确认读数，最小试探间隔自 30 s 起按 ×2 倍增，1800 s 封顶；一次确认的归因命中且读数成功即复位 30 s。

**数值推导（自洽性证明，BvA-1 消解）**：退避封顶 1800 s 的稳态 → 86400 ÷ 1800 = **48 次/天 < 96 封顶**，两验收口径（封顶、退避稳态）同时成立、不互斥（A 案「100 次/天 + 退避 5 min 封顶」稳态 288 次/天 > 100，两口径无法同时成立，故弃）。活跃期密集试探以防抖 5 s 为绝对下限，退避序列快速爬升，单日总量受 96 硬顶。

**单日总量上界** = 96（额度内试探）+ 6（保底读数，不计入额度）= **102 次/设备/天**。

**回滚**：额度与保底挂 `experimental_wake_quota` 配置键，**默认开**；关闭即回 v0.3.25 行为（无封顶无退避无保底），键关闭时诊断导出 manifest 之外不另设提示（本键非脱敏面）。

## 5. 裁决四（G-36 最低读数保障）：保底读数 N = 4 h

**保底周期 N 冻结为 4 小时**（`GUARANTEED_READ_INTERVAL = 14400 s`）。依据：C-1 选 A（无条件每 N 小时一次），A 建议 4 h、B 建议 ≤2 h；开工指令明确「每 4h 无条件保底穿透」，取 4 h。

**语义（逐条写死）**：
1. 触发：单设备距上次**确认读数** ≥ 4 h 即触发一次保底读数尝试，**无条件**（不依赖 Raw Input 已醒证据——隔夜长离无活动时已醒前提永不成立，且已醒判定依赖的正是失修中的 N-01，循环依赖）；
2. **判睡不戳**：设备处于 Sleeping 状态时不触发（D-33/G-36 红线，CI 断言判睡探测 = 0）；失效期穿透风险已登记，N-13 销项复核时回填复核（BvA-2 部分采纳落点）；
3. **不被封顶拦截**：每日 96 次硬顶不拦截保底；
4. **不计入额度**：保底尝试不消耗 PROBE_DAILY_CAP、不改变退避序列；
5. **可穿透 0xFF 负缓存每窗仅一次**：每 4 h 窗口内，保底尝试可穿透该设备的 0xFF 负缓存恰好一次；穿透不成功，缓存照旧生效到窗口结束；
6. 保底尝试计入 `guaranteed_read_attempts` 计数器，效果层可观测。

## 6. zero-match 占比验收阈值

**`ZERO_MATCH_RATIO_MAX = 0.05`（5%）。**

- 口径：`wake_miss_zero_match ÷（wake_successes + wake_miss_no_path + wake_miss_zero_match + wake_miss_no_fingerprint + wake_miss_ambiguous）`，运行窗口 ≥ 1 h 方纳入评估（短窗口分母噪声不判）。
- **同源机制**：常量定义于 `crates/app/src/core.rs`，单元测试读取本文档原文并断言文档中冻结值与常量一致（漂移即红）；fixture 回放测试断言多候选失配场景修复后命中 hit_relaxed（见第 8 节）。

## 7. 诊断计数器清单（本窗口新增，全部 run 内重置、入 DiagExport）

| 计数器 | 语义 | 落点 |
| --- | --- | --- |
| `probe_cap_daily_hits` | 因每日封顶（96 次）被抑制的试探次数 | tray Telemetry → DiagExport |
| `probe_backoff_skips` | 因退避窗口未到期被抑制的试探次数 | tray Telemetry → DiagExport |
| `guaranteed_read_attempts` | 保底读数尝试次数（第 5 节） | tray Telemetry → DiagExport |
| `wake_success_hit_exact` | 第一级精确指纹归因成功次数 | tray Telemetry → DiagExport |
| `wake_success_hit_relaxed` | 第二级放宽/绑定表消歧归因成功次数 | tray Telemetry → DiagExport |
| `run_started_at` | 运行起点时间戳（ISO 8601），frame_tx 速率分母 | DiagExport |
| `frame_tx` 速率（派生指标，D-3 补强） | `frame_tx ÷ 运行小时数`；N-14 一阶段指标集成员。基线参照：说明书最密档 288 次/天 ≈ 12 次/小时量级；修复后稳态是否回落**以计数器实测为准**，本文档不预写结论 | 由 `frame_tx` 与 `run_started_at` 派生，不新增原始计数器 |

## 8. 测试态注入双用例（E10 验收加厚②）

重枚举兜底改为测试态注入验收（修得越好越不自然触发，「真实触发过」不可作验收口径）：

1. **枚举空路径（enum-empty）**：模拟设备枚举返回空集，断言兜底重枚举被触发；
2. **probe 判死路径（BvA-4）**：模拟连续 2 轮静默（无响应）判死，断言该路径下重枚举可触发——真机断链点是 probe 判死而非枚举空，单用例不可证伪。

注入口收敛于 `reconnect.rs` 的测试态构造（仅 `#[cfg(test)]` 可及，运行态零触达）。

其余行为断言（全部落 windows-latest `cargo test --workspace`，无真机依赖）：
- 取证 A 真机路径样本固化 fixture 回放：多候选失配场景修复前 miss、修复后 hit_relaxed（fixture 从取证原文件重新提取核对）；
- 时间注入断言：试探 ≤ 封顶、触顶后保底仍发生且每 4 h 仅一次、判睡设备零探测、额度函数稳态不自斥（48 < 96）；
- 红线钉板：休眠态 `poll_decision` 恒 Skip、休眠设备零 frame_tx；
- zero-match 阈值同源测试（第 6 节）。

## 9. N-14 两阶段验收口径

- **一阶段（本窗口）**：诊断计数器**单源**验收打扰面，指标集 = zero-match 占比（≤ 5%）、probe_cap_daily_hits、probe_backoff_skips、guaranteed_read_attempts、wake_success_hit_exact / hit_relaxed、**frame_tx 速率（D-3）**；CSV 只作观察项（约三分之一时段归因 unknown，单独验收会得出不靠谱结论）。
- **二阶段**：N-03 修复且 unknown 占比 < 约定线后，启用诊断计数器 + CSV 双源（tools/recheck.py 扩展）；约定线数值在二阶段开工时拍板，本批不预写。

## 11. 红线与禁令（本窗口）

- 休眠设备零主动查询（D-33/G-36）：保底判睡不戳；试探不装填 Sleeping 之外的扩面。
- 绑定表内存态、禁持久化（BvA-3）。
- 不引入每 5 秒全槽扫描（第 2 节裁决）。
- 不碰 reconnect.rs REENUM_INTERVAL（C-4）。
- 本窗口不裁决 N-13（前半程零休眠记录），保底穿透失效期风险已登记、N-13 销项复核时回填。
