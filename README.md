# LogiVoltTray

**简体中文**（主位版本，内容如有出入以本版为准） | [English](README.en-US.md)

Windows 托盘直显罗技设备电量：在系统托盘图标上直接画出键盘 / 鼠标的实时电量数字，不用打开任何窗口。

[![GitHub Release](https://img.shields.io/github/v/release/isxulong/Logi-VoltTray)](https://github.com/isxulong/Logi-VoltTray/releases)

**下载**：当前最新版为 [v0.3.20](https://github.com/isxulong/Logi-VoltTray/releases/tag/v0.3.20)，下载 `volttray-tray.exe`（约 1.3 MB）即可；更多历史版本见 [Releases 页](https://github.com/isxulong/Logi-VoltTray/releases)（长期保留最近三个版本 N / N-1 / N-2，便于回退）。Windows 10 / 11（x64）双击即用，免安装、免管理员权限。最低系统版本 Windows 10 1809（API 依赖推断，未经真机矩阵核实，未验证）。

**下载后核验（可选但推荐）**：每个 Release 附 `volttray-tray.exe.sha256.txt`。PowerShell 一行核对：

```powershell
Get-FileHash .\volttray-tray.exe -Algorithm SHA256
# 输出的 Hash 应与同目录 .sha256.txt 文件内首列一致
```

> **未签名 EXE 首次运行可能被 Windows SmartScreen 拦截**（发布者无信誉积累——信誉随签名下载积累、逐步消除拦截；签名采购决策跟踪中，见 docs/experience/06 发布对账常设区）。若弹出蓝色「Windows 已保护你的电脑」提示：点「**更多信息**」→「**仍要运行**」即可放行；只放行本程序的这一个 EXE，不要据此放宽系统对其它未知程序的拦截设置。

## 功能列表

- **托盘电量直显**：托盘图标上直接绘制电量百分比数字（100% 显示「满」；真正未知显示「?」；设备离线显示「--」）。默认展示一台设备，右键菜单里每台设备一行，点击即可钉选切换展示对象。
- **广覆盖读取通道**：HID++ 2.0 统一接收器（Unifying / Bolt / Lightspeed）下挂设备、老款 HID++ 1.0 设备（寄存器直读）均可读取（已真机验证）；蓝牙直连与有线为实验性通道（未真机验证），见下文「实验性功能（未真机验证）」小节；电量来源自动逐级回退（统一电量 → 电量状态 → 电压换算 → HID 电源描述符）。
- **真实设备名**：显示「MX Keys」这类真实型号名（经 HID++ 设备名特性或接收器配对名寄存器读取），读不到时回退为「USB Receiver · 槽位 1」这类干净占位名，界面上不会出现裸「?」当名字。
- **分档电量配色**：按电量分档变色——默认 ≤20% 红、≤50% 黄、更高为绿；档数（2–5 档）、每档阈值与颜色全部可自定义。不按设备类型固定配色。
- **低电闪烁提醒**：电量低于阈值时图标以 1Hz 明暗闪烁；阈值用滑块在 5%–50% 间调节（默认 20%，步进 5%），阈值与开关的改动立即生效，不等下一轮轮询。左键单击托盘图标即可停止本次闪烁（右键是打开菜单，不会停闪），停闪保持到本次低电解除后自动重新武装；闪烁开关从「关」改回「开」会立即恢复闪烁；充电中的设备不闪烁、不提醒。
- **外观全自定义**：图标形状（圆角 / 直角 / 透明无背景）、背景（深色 / 浅色 / 自定义颜色）、字体、文字大小（40–160%）、背景覆盖度（20–100%），设置窗口里改动即时生效。
- **低电与读数过期通知**：电量跌破阈值、电量读数过期时发 Windows 通知。过期阈值与每台设备的轮询档位锚定（最短 90 秒，档位越长阈值越长——保证两次连续轮询失败才算过期证据），过期时灰显最后一次已知电量并发「电量显示已过期」通知，正常使用中不再误报「设备离线」；休眠不算过期。菜单里的「通知静音（仅关提示音）」只关闭提示音——弹窗照发、图标闪烁不受它管（闪烁的开关是「低电闪烁提醒」）。启动后首次读到电量就会立即判断低电并提醒，不等下一轮轮询。
- **开机启动开关**：右键菜单勾选 / 取消即可，写入注册表 HKCU Run 键（免管理员）。菜单、设置与配置文件任一侧改动都会同步到注册表，写入失败自动回退并告警，不会出现勾选态与实际自启分叉。
- **轮询间隔可调**：300 / 600 / 1800 / 3600 / 7200 秒五档（默认 1800 秒 = 30 分钟；最长档 7200 秒 = 2 小时），设置窗口下拉即改。每台设备独立计时（v0.3.16 起）：充电中的设备 15 秒一刷、拔线最多一个充电档内感知；常态设备走你设的档位；休眠设备不排程、零查询。一台设备进入充电不再抬高其它设备的查询频率（代价是：某台设备充电时，其它设备的拔电感知最长退化为自身档位时长）。设备枚举每个轮询周期自动刷新一次（30 秒仅为重枚举门控下限，并非每 30 秒例行枚举），新配对、接收器插拔自动识别。
- **鼠标休眠零耗电**：鼠标连续查询超时判定为休眠后，程序对它停止一切主动查询（对休眠中的鼠标发查询才是真费电）；靠系统 Raw Input 被动监听鼠标活动来唤醒，零射频成本。休眠期间托盘灰显最后已知电量，绝不当成「未知」。
- **设备诊断导出**：右键菜单「导出诊断信息…」导出脱敏诊断 JSON（v0.3.15 起弹出「另存为」对话框，保存位置与文件名由你选，默认文件名带本地时间戳；软件不会删除或清理任何导出文件），排查「读不到」时直接发这份文件即可。导出内容包括：设备发现、握手、电量查询、状态变更的完整事件流，最近一次设备枚举快照，以及运行日志末尾约 200 行——其中记录了设置应用（逐项差异）、闪烁开始 / 停止（含停止原因）、通知发出 / 被静音 / 失败等事件，反馈问题时一般不必再单独翻日志。
- **多实例防护**：命名互斥锁保证只运行一个实例；重复启动会弹窗提示「已在运行」并退出，不会出现托盘里摞一排图标。
- **交互省心**：双击 EXE 即启动；左键单击图标停止低电闪烁；右键菜单覆盖全部常用操作（立即刷新、开关、设置、诊断、退出）；点退出即退，IO 线程 200 毫秒分片睡眠随叫随醒，不卡界面。

### 实验性功能（未真机验证）

以下功能核心逻辑由单元测试锁定、Windows 侧接线经 CI（windows-latest）构建验证，但真机行为尚未验证；如遇与描述不符，请用「导出诊断信息…」导出诊断文件反馈。**四项功能新装默认关**（v0.3.21 起；老用户升级不受影响、保持开启）——需要哪项，在 `config.toml` 把对应键置 `true` 即可开启（改完约 5 秒热重载生效，详见「配置文件」小节）。

- **重启即显最后已知电量**（v0.3.16 起）：新装默认关，在 `config.toml` 置 `experimental_persist_last_known = true` 开启。每台设备的最后一次电量读数持久化到 `%LOCALAPPDATA%\LogiVoltTray\last_known.json`（与配置文件分开放置，不随漫游配置同步；原子写入，文件损坏自动回退、不阻塞启动）。重启后立即灰显最后已知电量（虚拟条目，不发起任何设备查询，有数据才出现对应菜单项）；关机时做最终落盘，崩溃 / 掉电也能保住最近一次状态。以设备物理身份为主键，同名设备不会因重启互相混淆。

- **耗电统计与导出**（v0.3.16 起）：新装默认关，在 `config.toml` 置 `experimental_stats = true` 开启。读取 / 休眠 / 充电等事件按行落盘 `%LOCALAPPDATA%\LogiVoltTray\stats.jsonl`（单文件 10MB 封顶、触顶轮转，与归档文件合计不超过 20MB；接近容量上限时会先弹「统计历史即将轮转，建议先导出」提示再轮转）。右键菜单「导出耗电统计…」与诊断导出一样走系统「另存为」对话框：CSV 必选，可勾选同时生成自包含 HTML 可视化报告（单文件零外链、断网双击可看——电量曲线、每日耗电对比、时长占比、分段明细、近 7 天活跃耗速率）与 JSON 原始事件序列，还可勾选匿名化（设备键显示为 D1、D2…，真实设备名保留）。统计按时间轴分活跃 / 休眠 / 充电 / 未知四类归因，时间倒流、超过 7 天的缺口等异常如实标注，不产生负耗电速率。仓库附带 `volttray/tools/recheck.py` 复算脚本（纯 Python 标准库）：供排查与验收使用，拿 stats.jsonl 对导出的 CSV / HTML / JSON 逐项独立复算对账，确认统计口径无误。

- **按设备计时轮询**（v0.3.16 起）：新装默认关，在 `config.toml` 置 `experimental_per_device_polling = true` 开启。充电中的设备 15 秒一刷、休眠设备不排程零查询等新逻辑尚未真机验证，详见「轮询间隔可调」条目。
- **蓝牙直连与有线设备读取**：新装默认关，在 `config.toml` 置 `experimental_bluetooth_wired = true` 开启。代码通路已支持，尚未真机验证，如读不到请用「导出诊断信息…」导出诊断文件发我们排查。

## 快速上手

1. 从 [Releases 页](https://github.com/isxulong/Logi-VoltTray/releases) 下载 EXE，放到任意目录。
2. 双击运行，托盘区出现电量图标，数字就是默认展示设备的当前电量。
3. **右键菜单**：
   - 顶部设备区：每台已识别设备一行（含电量 / 充电中 / 休眠中 / 离线状态），点击钉选为托盘展示对象；
   - 「立即刷新（当前间隔 N 秒）」：立刻跑一轮电量查询；
   - 「低电闪烁提醒」「通知静音（仅关提示音）」「开机自启」：三个即点即用的开关；
   - 「设置…」「导出诊断信息…」「导出耗电统计…」「退出」。
4. **设置窗口**（改动即时生效，无确定 / 取消按钮）：
   - 外观：图标形状、背景、字体颜色（「自动」= 按电量分档，「自定义」= 固定色）、字体、文字大小、背景覆盖度；
   - 分档：档数、各档阈值、各档颜色（取色器自选）；
   - 轮询间隔：五档下拉；
   - 低电提醒：闪烁开关 + 阈值滑块（5–50%），改动立即生效、不等轮询周期。
5. 想启用实验性功能（最后已知电量 / 耗电统计 / 按设备计时轮询 / 蓝牙与有线读取）：新装默认全关，在 `config.toml` 把对应 `experimental_*` 键置 `true` 即可，逐条说明见上文「实验性功能」小节。

## 配置文件

配置文件位于 `%APPDATA%\LogiVoltTray\config.toml`，扁平键值、无 section，首次运行自动生成。

- **热重载**：手改保存后约 5 秒内被程序感知并生效（按修改时间轮询，不占用设备查询），无需重启；设置窗口的改动也会实时写回该文件，双向一致。
- **手写配置文件视为存量**：手工编写 / 从旧版带过来的 `config.toml`（无 v0.3.21 迁移标记）按存量口径迁移——四个 `experimental_*` 键缺失的补 `true`（保持老行为），显式写过的值一律保留，不会被迁移覆盖。
- **容错**：未知键忽略并产生诊断警告；越界值自动钳制或吸附到最近合法档位，不会因此拒绝启动。
- **另有两份数据文件**（`%LOCALAPPDATA%\LogiVoltTray\` 下，v0.3.16 起，不随漫游配置同步）：`last_known.json`（最后已知电量，重启即显用）与 `stats.jsonl`（耗电统计事件流，10MB 封顶轮转）。

## 日志与诊断

排查「读不到设备 / 电量显示 ?」时用到这两样：

- **运行日志** `%APPDATA%\LogiVoltTray\logi-volttray.log`：从启动第一阶段就开始记录（含配置加载警告、启动失败原因），即使是「双击没反应」这类启动即退的场景也有留痕。设置应用（逐项差异）、闪烁启停（含停止原因）、通知派发 / 静音 / 失败等事件也都记录在内。
- **诊断导出**：右键菜单「导出诊断信息…」→「另存为」对话框自选位置保存 `LogiVoltTray-diag-export-<时间戳>.json`（v0.3.15 起；更早版本为写入配置目录并弹窗告知路径）：脱敏后的诊断事件流（序列号等已打码，记录了每个通道、每个设备槽位的握手与电量查询结果）+ 最近一次设备枚举快照 + 运行日志末尾约 200 行。反馈问题时请附上这份文件。
- **隐私披露（v0.3.20 起）**：诊断导出自 v0.3.20 起自动将导出文本中的本机用户名（`C:\Users\<名>` 路径段）替换为 `<USER>`，设备名按出现顺序替换为「设备N」。此前版本导出的文件可能含本机用户名与设备名，请在提交前自行检查删除。
- **反馈渠道**：问题请通过 [issues](https://github.com/isxulong/Logi-VoltTray/issues) 提交（有 bug-report 模板引导，请附上『导出诊断信息…』产生的 JSON 文件）。若导出文件来自 v0.3.20 之前版本，可能含本机用户名，请在提交前删除该字段。

## 设计理念

- **零鼠标电池开销**：休眠判定后零主动查询，唤醒只靠系统层被动监听（Raw Input），轮询间隔可一路拉到 2 小时——程序自身的耗电极低，更不会为了读电量去叫醒鼠标。
- **单 HID IO 线程**：全部设备的读写都在一个 IO 线程内串行进行，杜绝多线程抢同一 HID 通道；跨线程只走 channel 消息，GUI 永不直接碰设备。
- **协议层纯编解码**：`volttray-protocol` crate 不做任何 I/O、不依赖系统时间，纯粹的组帧 / 解帧与映射逻辑，可用黄金样例与 proptest 充分验证。

## 从源码构建

主工程在 `volttray/` 子目录（Rust workspace），仅支持 Windows。

```powershell
git clone https://github.com/isxulong/Logi-VoltTray.git
cd Logi-VoltTray\volttray
cargo build --release --locked -p volttray-tray
```

产物为 `volttray\target\release\volttray-tray.exe`。要求 Rust stable（仓库 `rust-toolchain.toml` 锁定 1.90.0，`rustup` 会自动按此安装）与 MSVC 构建环境。

**云端构建**：推送到 `main` 即触发 CI（windows-latest）：`cargo fmt --check`（不一致即失败、作者本地修复）、`clippy -D warnings`、全量测试、`cargo build --release --locked` 并把 EXE 作为 artifact 上传；Releases 页的安装包即由此流水线产出。本地没有 Rust 环境时，fork 后 push 即可在云端取到 EXE。

**唯一分发形态为 Rust 版 `volttray-tray.exe`**。仓库根的 `logi_*.py` 是受维护的协议参考实现与黄金向量生成器（`volttray/fixtures/gen_golden.py` 产出 `fixtures/golden/` 向量，CI 每轮以 `python -m unittest discover -s tests` 跑协议冻结测试），不再经独立流水线产出 Python 版 EXE。

`red/` 目录出处：早期 Python「红版」HID++ 协议实现（红蓝对抗 T1 基线代理；v0.3.17 起按合并版逆推重建入库，原件不可考），是协议冻结测试 `tests/test_protocol_freeze.py` 的对照基线——29 个协议常量须逐一相等、11 个协议函数源码须逐行一致。它与 `volttray/`（现行 Rust 工程）的关系：`volttray/` 是唯一出货工程，`red/` 与根目录 `logi_*.py` 均为协议参考实现，不参与构建与分发。
